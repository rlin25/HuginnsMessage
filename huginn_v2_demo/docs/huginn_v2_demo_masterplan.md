## The Completed System — Plain English Description

The Huginn v2 demo is a single self-contained HTML file that allows recruiters to experience the Huginn v2 trade exception triage system without cloning the repository or running any local services. It presents a Swagger-inspired dark-themed UI with five pre-built scenarios covering all three of Huginn's execution paths. The recruiter selects a scenario, clicks Execute, and watches a sequential animated visualization of the LangGraph state machine — SVG nodes lighting up in path order — while a live Claude API call (routed through a Cloudflare Worker proxy) generates a simulated Huginn response. The response reveals in three stages: the animated node graph, the retrieved regulatory chunk cards, and the confidence score / reasoning trace / resolution steps cards. The framing copy states explicitly that responses are generated by Claude simulating Huginn's pipeline, with architecture, execution paths, and regulatory document references accurate to the real system. The file is deployed to GitHub Pages with no build step. A Cloudflare Worker handles the API proxy, injecting the API key server-side so it does not appear in the HTML.

## Technology Decisions

**No build step.** The demo is vanilla HTML + CSS + JavaScript. No Node.js, no bundler, no npm. CDN imports only.

**CDN imports used:**
- React + ReactDOM: `https://unpkg.com/react@18/umd/react.production.min.js`
- React DOM: `https://unpkg.com/react-dom@18/umd/react-dom.production.min.js`

- Tailwind CSS: `https://cdn.tailwindcss.com`
- shadcn/ui primitives: implemented as inline components styled with Tailwind — shadcn has no CDN; its components are copy-paste by design. Implement Card, Badge, Button, Tabs, ScrollArea as lightweight inline implementations matching shadcn's visual style.

## Subplan 1 — Cloudflare Worker Proxy

### What to build
`worker/index.js` — a Cloudflare Worker that proxies requests to the Anthropic API, injecting the API key from a Worker environment variable and returning the response with permissive CORS headers.

### Why this subplan is first
The API call is the demo's functional core. Confirming the proxy works before any HTML is written means subplan 5 is not blocked by infrastructure when it should be blocked only by implementation.

### Implementation instructions

The Worker handles two request types:

**OPTIONS (preflight):**
Return 200 with CORS headers:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

**POST:**
1. Read the request body as JSON.
2. Forward to `https://api.anthropic.com/v1/messages` with:
   - All headers from the original request, plus:
   - `x-api-key: <ANTHROPIC_API_KEY environment variable>`
   - `anthropic-version: 2023-06-01`
3. Return the Anthropic response body with CORS headers appended.

```javascript
export default {
  async fetch(request, env) {
    if (request.method === 'OPTIONS') {
      return new Response(null, {
        headers: {
          'Access-Control-Allow-Origin': '*',
          'Access-Control-Allow-Methods': 'POST, OPTIONS',
          'Access-Control-Allow-Headers': 'Content-Type',
        }
      });
    }

    const body = await request.json();
    const response = await fetch('https://api.anthropic.com/v1/messages', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'x-api-key': env.ANTHROPIC_API_KEY,
        'anthropic-version': '2023-06-01',
      },
      body: JSON.stringify(body),
    });

    const data = await response.json();
    return new Response(JSON.stringify(data), {
      headers: {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*',
      }
    });
  }
};
```

**Deployment steps:**
1. Create a new Cloudflare Worker in the Cloudflare dashboard (free tier).
2. Paste the worker source.
3. Add environment variable `ANTHROPIC_API_KEY` with the demo API key value.
4. Deploy. Note the Worker URL (e.g. `https://huginn-demo.YOUR-SUBDOMAIN.workers.dev`).
5. Define this URL as `WORKER_URL` constant in `index.html` during subplan 5.

### Gate — Subplan 1

## Subplan 4 — StateGraph SVG + Animation

### What to build
`StateGraph` component — full SVG node graph with all seven nodes, all six edges, arrowheads, and the full animation system. Driven by stub `activePath` prop for gate testing.

### Interface contract reference
Component 4 — StateGraph (full specification including node coloring table)
Shared Data — Node Graph Definition (NODES and EDGES constants, active nodes per path)
UI Spec — StateGraph SVG Specification (canvas, node dimensions, node positions, edge routing rules, visual states, animation sequence, loading state)

### Implementation instructions

**NODES constant** — use the coordinates from the UI spec (not the interface contract — the UI spec updated the canvas to 700×500px and recalculated positions):

```javascript
const NODES = [
  { id: "classify",           label: "classify",           cx: 350, cy: 60  },
  { id: "retrieve",           label: "retrieve",           cx: 200, cy: 175 },
  { id: "reason",             label: "reason",             cx: 200, cy: 280 },
  { id: "decide",             label: "decide",             cx: 200, cy: 385 },
  { id: "auto_resolve",       label: "auto_resolve",       cx: 90,  cy: 465 },
  { id: "escalate",           label: "escalate",           cx: 310, cy: 465 },
  { id: "escalate_fast_exit", label: "escalate_fast_exit", cx: 530, cy: 175 },
]
```

Node rect: `x = cx - 70`, `y = cy - 20`, `width = 140`, `height = 40`, `rx = 6`.

**EDGES** — define as specified in the interface contract. Each edge is a `<path>` element. Implement as cubic bezier curves. Routing rules from the UI spec:
- `classify → retrieve`: exits bottom-left of classify, enters top of retrieve, slight leftward curve.
- `classify → escalate_fast_exit`: exits bottom-right of classify, enters top of escalate_fast_exit, rightward curve.
- `retrieve → reason`, `reason → decide`: straight vertical lines.
- `decide → auto_resolve`: diagonal left from bottom-left of decide to top of auto_resolve.
- `decide → escalate`: slight rightward curve from bottom of decide to top of escalate.

**Arrowhead markers** — define two `<marker>` elements in `<defs>`: `arrow-neutral` (fill `--panel-border`) and `arrow-active` (fill `--swagger-green`). Each edge uses the appropriate marker based on whether it's on the active path.

**Node visual states** — three states per node, all CSS transition `all 400ms ease`:
- Neutral: `fill: var(--panel-bg)`, `stroke: var(--panel-border)`, `stroke-width: 1.5`, label color `--text-secondary`, opacity 1.
- Active: `fill: var(--node-active-bg)`, `stroke: var(--swagger-green)`, `stroke-width: 2`, label color `--swagger-green`, opacity 1.
- Dimmed: `fill: var(--panel-bg)`, `stroke: var(--panel-border)`, `stroke-width: 1`, label color `--text-secondary`, opacity 0.3. Dimmed nodes on fast-exit and rejection paths also render a `skipped` label 14px below the node rect in 9px `--text-secondary` text.

**Active path → node state mapping** — implement exactly as specified in the interface contract node coloring table. Define as a constant:
```javascript
const PATH_ACTIVE_NODES = {
  standard_auto_resolve: ["classify", "retrieve", "reason", "decide", "auto_resolve"],
  standard_escalate:     ["classify", "retrieve", "reason", "decide", "escalate"],
  fast_exit:             ["classify", "escalate_fast_exit"],
  rejection:             ["classify"],
}
```

Nodes not in the active list for the current path are dimmed. Nodes not yet reached during animation are neutral.

**Animation sequence** — when `status` changes to `"animating"`:
1. Start with all nodes neutral.
2. Step through `PATH_ACTIVE_NODES[activePath]` in order, activating one node per `NODE_STAGGER_MS` (300ms) using `setTimeout` chains.
3. After the last active node activates, wait `NODE_TRANSITION_MS` (400ms), then dim all remaining nodes simultaneously.
4. Fire `onAnimationComplete` callback.

**Loading state** — when `status === "loading"`: all nodes neutral. A pulsing SVG `<circle>` centered on the classify node (`cx=350, cy=60`), `r=36`, `stroke: var(--swagger-green)`, `fill: none`, CSS animation cycling opacity 0.6→0→0.6 over 1.2s.

**Props for gate testing** — expose a `debugPath` prop that allows directly setting `activePath` and `status` from a temporary debug control outside the component. Remove before subplan 5.

### Implementation instructions

**`WORKER_URL` constant** — define at the top of the script block:
```javascript
const WORKER_URL = 'https://huginn-demo.YOUR-SUBDOMAIN.workers.dev';
```

**API call function:**
```javascript
async function callHuginn(scenario) {
  const response = await fetch(WORKER_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 1000,
      system: SYSTEM_PROMPT,
      messages: [{ role: 'user', content: JSON.stringify({ exception: scenario.payload }) }]
    })
  });
  const data = await response.json();
  const text = data.content[0].text;
  // Strip markdown fences defensively
  const clean = text.replace(/^```json\n?/, '').replace(/\n?```$/, '').trim();
  return JSON.parse(clean);
}
```

**`SYSTEM_PROMPT` constant** — define verbatim from the interface contract API Call Specification section. Do not paraphrase or shorten.

**`activePath` derivation from parsed response:**
```javascript
function deriveActivePath(parsed) {
  if (parsed.path === 'fast_exit') return 'fast_exit';
  if (parsed.path === 'rejection') return 'rejection';
  return parsed.outcome === 'auto_resolve' ? 'standard_auto_resolve' : 'standard_escalate';
}
```

**Full interaction sequence** — implement exactly as specified in the interface contract App (Root) section. Key points:
- On Execute: set `isLoading: true`, `graphStatus: "loading"`, clear prior output.
- On API success: set `graphStatus: "animating"`, wire `activePath`.
- `onAnimationComplete` callback (from subplan 4): set `graphStatus: "complete"`, then branch on path for retrieval/response visibility per the timing constants.
- On API error: set `graphStatus: "error"`, set `errorMessage`.
- On scenario select: reset all output state.

**Timing constants** — define as named constants, not inline numbers:
```javascript
const NODE_TRANSITION_MS = 400;
const NODE_STAGGER_MS = 300;
const POST_GRAPH_DELAY_MS = 1500;
const POST_RETRIEVAL_DELAY_MS = 1500;
```
