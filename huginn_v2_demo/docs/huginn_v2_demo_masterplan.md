## The Completed System — Plain English Description

The Huginn v2 demo is a single self-contained HTML file that allows recruiters to experience the Huginn v2 trade exception triage system without cloning the repository or running any local services. It presents a Swagger-inspired dark-themed UI with five pre-built scenarios covering all three of Huginn's execution paths. The recruiter selects a scenario, clicks Execute, and watches a sequential animated visualization of the LangGraph state machine — SVG nodes lighting up in path order — while a live Claude API call (routed through a Cloudflare Worker proxy) generates a simulated Huginn response. The response reveals in three stages: the animated node graph, the retrieved regulatory chunk cards, and the confidence score / reasoning trace / resolution steps cards. The framing copy states explicitly that responses are generated by Claude simulating Huginn's pipeline, with architecture, execution paths, and regulatory document references accurate to the real system. The file is deployed to GitHub Pages from the `HuginnsMessage/` monorepo. A Cloudflare Worker handles the API proxy, injecting the API key server-side so it does not appear in the HTML.

## Technology Decisions

**No build step.** The demo is vanilla HTML + CSS + JavaScript. No Node.js, no bundler, no npm. CDN imports only.

**CDN imports used:**
- React + ReactDOM: `https://unpkg.com/react@18/umd/react.production.min.js`
- React DOM: `https://unpkg.com/react-dom@18/umd/react-dom.production.min.js`
- Babel standalone (JSX transpilation in browser): `https://unpkg.com/@babel/standalone/babel.min.js`
- Tailwind CSS: `https://cdn.tailwindcss.com`
- IBM Plex Mono: `https://fonts.googleapis.com/css2?family=IBM+Plex+Mono:wght@600&display=swap`

**shadcn/ui was not used.** The UI spec originally planned shadcn/ui components. The implementation uses lightweight inline components styled with direct CSS properties. All components (tab strip, cards, badges, buttons, scroll areas) are implemented as plain React with inline styles. This is consistent with the masterplan's own subplan 3 instruction: "Implement a lightweight tab strip directly."

**Cloudflare Worker** handles the Anthropic API call. The Worker URL is `https://huginn-demo.richard-lin2025.workers.dev`, defined as a constant in `index.html`. The API key lives only in the Worker environment variable — not in the HTML. The Worker uses service worker `addEventListener` format, not ES module format.

## Subplan 1 — Cloudflare Worker Proxy

### What to build
`worker/index.js` — a Cloudflare Worker that proxies requests to the Anthropic API, injecting the API key from a Worker environment variable and returning the response with permissive CORS headers.

### Why this subplan is first
The API call is the demo's functional core. Confirming the proxy works before any HTML is written means subplan 5 is not blocked by infrastructure when it should be blocked only by implementation.

### Implementation instructions

The Worker handles two request types:

**OPTIONS (preflight):**
Return 200 with CORS headers:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

**POST:**
1. Read the request body as JSON.
2. Forward to `https://api.anthropic.com/v1/messages` with:
   - `x-api-key: <ANTHROPIC_API_KEY environment variable>`
   - `anthropic-version: 2023-06-01`
3. Return the Anthropic response body with CORS headers appended.

**Implemented format (service worker, not ES module):**
```javascript
addEventListener('fetch', event => {
  event.respondWith(handleRequest(event.request));
});

async function handleRequest(request) {
  if (request.method === 'OPTIONS') {
    return new Response(null, {
      headers: {
        'Access-Control-Allow-Origin': '*',
        'Access-Control-Allow-Methods': 'POST, OPTIONS',
        'Access-Control-Allow-Headers': 'Content-Type',
      }
    });
  }

  const body = await request.json();
  const response = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-api-key': ANTHROPIC_API_KEY,
      'anthropic-version': '2023-06-01',
    },
    body: JSON.stringify(body),
  });

  const data = await response.json();
  return new Response(JSON.stringify(data), {
    headers: {
      'Content-Type': 'application/json',
      'Access-Control-Allow-Origin': '*',
    }
  });
}
```

Note: The masterplan originally specified ES module format with `export default { async fetch(request, env) {...} }` and `env.ANTHROPIC_API_KEY`. The deployed Worker uses service worker format with `ANTHROPIC_API_KEY` as a global binding. See Decision 24 in design_decisions.md.

**Deployment:**
- Worker name: `huginn-demo`
- Worker URL: `https://huginn-demo.richard-lin2025.workers.dev`
- Environment variable: `ANTHROPIC_API_KEY`

### Gate — Subplan 1
Complete. Worker is live and responding at `https://huginn-demo.richard-lin2025.workers.dev`.

## What Claude Code Must Not Do

- Do not introduce a build step (no npm, no bundler, no compilation required to open the file)
- Do not use localStorage or sessionStorage — all state is in-memory React state
- Do not import shadcn from npm — implement shadcn-style components as inline lightweight implementations
- Do not hardcode any color values outside the `:root` CSS custom properties block
- Do not put the Anthropic API key in `index.html` — it lives only in the Cloudflare Worker environment variable
- Do not abbreviate or paraphrase the system prompt — use it verbatim from the interface contract
